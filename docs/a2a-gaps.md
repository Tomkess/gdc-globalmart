# What an orchestrator needs from GoodData, and what is missing

## Agent discovery

Generated by `gd-agents profile` from a real run against 4 workspace(s) on 2026-09-21. Not written from memory.

- All 4 workspaces advertise an identical A2A agent card ('GoodData Analytics AI Agent'), so the card cannot be used to tell them apart or to route between them. Subject matter is not discoverable over A2A.
- Advertised skills are protocol capabilities (visualization, key-driver analysis and so on), identical across workspaces holding different data models. They describe what the agent can do, never what it knows about.
- Building a routing description required reading datasets, memoryItems, metrics through the metadata API — calls outside A2A, needing credentials beyond what an agent connection carries. An orchestrator that only holds an A2A endpoint cannot produce these descriptions.
- 4 workspace(s) carry no description of their own (globalmart-customer, globalmart-marketing, globalmart-store-ops, globalmart-ecommerce), so the subject matter had to be inferred from dataset and metric names.
